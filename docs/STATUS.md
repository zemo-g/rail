## Dependency boundary

The seed binary has **no C**: the GC and runtime are ARM64 assembly embedded in the
compiler, and since v5.2.0 it assembles, links, and code-signs itself (no `as` / `ld` /
`codesign`). It links one system library, `libSystem` (`otool -L rail_native`), the
kernel interface every macOS process has. Everyday `./rail_native file.rail` builds still
use the system `as` and `ld`. Optional concurrency, GPU (Metal), and JIT features use a small
asm/ObjC/C boundary - 33 in-tree non-Rail files, each named in [`SHIMS.md`](../SHIMS.md).

## Backends

ARM64 macOS (native) - Linux ARM64 - Linux x86_64 - WebAssembly (compiles; runtime
fragile) - Cortex-M4 (Thumb-2) - RISC-V rv32imc.

## Known surprising behaviors

Compilation proves a program is *accepted by the binary you run*, not that it is
*correct*. These are defined, but easy to trip over:

- `&&` / `||` do not short-circuit - both sides always evaluate
- `split` takes a single-character delimiter (use `str_split` for multi-char)

## What this proves

Signed, reproducible provenance: where the bytes came from and how to reproduce them.
Not a proof of correctness, and not numerical truth. The defensible claim is **check
me**, never *proof of truth*.
