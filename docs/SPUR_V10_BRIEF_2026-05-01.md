## Content-specificity (compile.rail split ablation)

| Corpus | Bytes | Bench |
|---|---:|---:|
| compile.rail full | 362,075 | 7/30 (best seed) |
| **compile.rail half-A** (lexer/parser/typecheck) | 181,565 | **0/30** |
| **compile.rail half-B** (codegen/emit/x86) | 180,510 | **5/30** |

The lever lives in compile.rail's **back half** — codegen patterns, ADT match emit, x86 backend. Bench tasks are codegen-biased; back-half training matches the prompt distribution. Front half (parser) gives no transfer.

## Why compile.rail wins

`tools/compile.rail` is 4,690 lines of structurally cohesive self-hosting Rail. Single author, consistent style, idioms, scoping. **Training on it concentrates the model on one coherent code distribution.** Mixing with anything else dilutes (4-arm ablation: ascii+curriculum=1/30; compile.rail+curriculum=1/30; ascii+compile.rail=0/30; multi-coherent=0/30).

This is the structural advantage Spur owns: a 4,690-line self-hosting compiler in our target language. AlphaCode-2, CodeRL, RLVR papers all train on heterogeneous web-scraped code. Spur trains on one program that reaches a fixed point under itself — and the compile rate confirms the substrate matters.

## Bug to file

`rail_native` exits 0 even when `ld` fails (undefined symbols). Mid-session this caused a measurement bug (false-positive 24/30 from a strip-grade tool using `&& echo PASS`). Honest grade (`ld: OK` string match — bench harness's standard test) is the only reliable signal. Fix: `_rail_main` should propagate `ld` failure as non-zero exit. ~30 min `compile.rail` patch + 2-cycle bootstrap.
